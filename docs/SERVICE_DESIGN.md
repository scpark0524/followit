# Action Keeper (가칭) 서비스 설계서

## 1. 포지셔닝

### 왜 이 주제인가

가장 큰 약점부터 정리:

> "클로바노트, Zoom AI, Notion AI도 회의 요약과 액션아이템 추출을 해주는데요?"

맞습니다. 그래서 이 프로젝트의 경쟁 무대는 **"회의록"이 아니라 "실행 관리"**입니다.

### 발표용 메시지
> "기존 도구는 회의를 '기록'합니다. 우리는 회의를 '완결'합니다."

### Circleback과의 정밀 비교

| 우리 워크플로 | Circleback | 판정 |
|---|---|---|
| STAGE 1. 녹음 → 텍스트 + 화자 구분 | O (오히려 더 잘함) | 완전히 겹침 |
| STAGE 2. 결정/액션/담당자/기한 추출 | O (리뷰어가 "최고 기능"으로 꼽음) | 완전히 겹침 |
| STAGE 3-1. 태스크를 업무 도구에 등록 | O | 겹침 |
| STAGE 3-2. R&R 추천, 선후관계 타임라인 | X (대화에 나온 담당자만 배정) | **일부 차이** |
| STAGE 4. 팔로업, 답변 해석, 지연 감지 | X (등록 이후는 외부 도구에 맡김) | **빈 영역** |
| STAGE 5. 미완료 → 다음 회의 안건 | X | **빈 영역** |

**냉정한 결론**: STAGE 1~2를 발표 중심에 두면 "따라 만든 거"가 됨.
STAGE 4~5를 중심에 두면 같은 시장의 **다른 문제를 푸는** 프로젝트가 됨.

### 차별화 포인트: Accountability Loop

| | Circleback | Action Keeper |
|---|---|---|
| 해결하는 문제 | 회의록 작성이 귀찮다 | 회의에서 정한 일이 실행되지 않는다 |
| 일이 끝나는 시점 | 태스크가 등록되는 순간 | 태스크가 완료되는 순간 |
| 성공 지표 | 회의록 품질, 절약한 시간 | **기한 내 완료율** |
| AI의 역할 | 요약하고 추출 | 물어보고, 해석하고, 조정 |

## 2. 5단계 워크플로 상세

### STAGE 1. 기록
- **트리거**: Google Drive에 녹음 파일 업로드 감지
- **처리**: STT API로 텍스트 변환 + 화자 구분
- **출력**: 타임스탬프 + 화자 라벨이 달린 전사문

### STAGE 2. 추출 (LLM ①)
- **입력**: 전사문 + 회의 메타정보 (날짜, 참석자)
- **처리**: Claude/GPT가 구조화된 JSON 추출
- **핵심 필드**:
  - 결정사항, 액션아이템, 담당자, 기한
  - **근거 발화 + 타임스탬프** (환각 방지)
  - **확신도 (상/중/하)** (HITL 효율화)
  - 담당자/기한 없으면 반드시 "미정"

### STAGE 3. R&R + 타임라인 (LLM ② + LLM ③)
- **LLM ②**: 담당자 "미정" 항목에 대해 R&R 추천
  - 팀원 역할 프로필 + 현재 업무량 참고
  - "왜 이 사람인지" 이유 제시
- **LLM ③**: 타임라인 생성
  - 선후관계 파악 ("설문 끝나야 분석 가능")
  - 마일스톤(중간발표일 등)에서 역산하여 기한 제안
- **HITL**: Slack 승인 카드 발송
  - 확신도 "하" 항목만 강조
  - 수정/승인/거절 버튼
  - **n8n Wait 노드**로 사람 응답까지 대기
- **등록**: 승인된 것만 Notion DB에 생성

### STAGE 4. 추적 (LLM ④)
- **트리거**: 매일 09:00 (Cron)
- **로직**:
  ```
  Notion에서 미완료 태스크 조회
    ↓
  기한별 분류:
    D-2: 사전 리마인드 (Slack DM)
    D-day: 완료 확인 요청
    D+1~3: 지연 알림 + 사유 입력 요청
    D+3~: PM 에스컬레이션
    ↓
  담당자 답변 수신 (Slack Trigger)
    ↓
  LLM ④가 자유 답변 해석:
    completed / on_track / blocked / at_risk
    ↓
  분기:
    blocked → PM 에스컬레이션
    at_risk → 후속 업무 담당자 알림 + 새 일정 제안
    no_response (24h) → 재질문, 그래도 없으면 PM 알림
  ```

### STAGE 5. 순환 (LLM ⑤)
- **트리거**: 매주 금요일 17:00 (또는 다음 회의 전날)
- **출력**: 다음 회의 안건 초안
  - 완료된 일 / 미완료 / 막힌 일 / 보류 결정
  - 미완료·막힌 일이 안건 맨 위
- → 다음 회의 녹음 → STAGE 1 (닫힌 루프)

## 3. AI가 꼭 필요한 이유

> 교수님이 반드시 물어볼 질문

1. **맥락 속 약속 파악**: "그럼 그건 제가 한번 볼게요" → 액션아이템 (키워드 규칙 불가)
2. **암묵적 기한 해석**: "중간발표 전까지는 돼야죠" → 10/24로 변환 (맥락 이해 필요)
3. **자유 답변 해석**: "아 그거 자료가 아직 안 와서요…" → blocked 분류 (규칙 불가)

## 4. 리마인드 메시지 예시

```
[Action Keeper] 리마인드
📋 마케팅 예산안 수정본 작성
👤 담당: 이대리
📅 기한: 내일 (10/31)
💬 근거: "이대리가 금요일까지 수정본 만들어주세요" (10/24 회의)

[완료] [진행 중] [막힘] [연기 요청]
```

## 5. 주간 리포트 예시

```
=== Action Keeper 주간 리포트 (10/21~10/25) ===

📊 이행률: 7/10 (70%) ← 지난주 63%

✅ 완료 (7건)
  - A1. 마케팅 예산안 수정본 작성 (이대리, 기한 내)
  ...

⚠️ 미완료 (3건) → 다음 회의 안건 제안
  - A8. 고객 설문 설계 (최인턴, 3일 지연, blocker: 설문 도구 미정)
  ...

📋 다음 회의 안건 초안:
  1. [팔로업] 고객 설문 설계 blocker 해소 (최인턴)
  2. [팔로업] 서버 마이그레이션 일정 확정 (김팀장)
  3. [신규] ...
```

## 6. 전략적 제안: 경쟁하지 말고 올라타기

STAGE 1~2는 기존 도구가 잘함. 시간을 여기에 쓰지 말고:
- 기존 노트테이커의 결과물을 입력으로 받아 STAGE 3~5에 집중
- 또는 검증된 n8n 템플릿을 가져와 커스텀

> "회의 AI 시장은 '기록'까지 왔습니다. 우리는 그 다음, '실행'의 빈칸을 채웁니다."

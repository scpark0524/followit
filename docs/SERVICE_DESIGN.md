# FollowIt (팔로잇) 서비스 설계서

## 1. 포지셔닝

### 왜 이 주제인가

가장 큰 약점부터 정리:

> "클로바노트, Zoom AI, Notion AI도 회의 요약과 액션아이템 추출을 해주는데요?"

맞습니다. 그래서 이 프로젝트의 경쟁 무대는 **"회의록"이 아니라 "실행 관리"**입니다.

### 발표용 메시지
> "기존 도구는 회의를 '기록'합니다. 우리는 회의를 '완결'합니다."

### Circleback과의 정밀 비교

| 우리 워크플로 | Circleback | 판정 |
|---|---|---|
| STAGE 1. 회의 기록·전사문 확보 | O (오히려 더 잘함) → 우리는 연동으로 올라탐 | 겹침 회피 |
| STAGE 2. 회의 연결·맥락 관리 | X (회의 단위로 끝, 회의 간 연결 없음) | **빈 영역** |
| STAGE 3. 액션 추출 + R&R 추천 + HITL | 추출 O / R&R 추천·확인 X (대화에 나온 담당자만) | **일부 차이** |
| STAGE 4. 선행관계 타임라인 | X | **빈 영역** |
| STAGE 5. 팔로업, 답변 해석, 지연 감지, 다음 안건 | X (등록 이후는 외부 도구에 맡김) | **빈 영역** |

**냉정한 결론**: 녹음·전사·추출을 발표 중심에 두면 "따라 만든 거"가 됨.
회의 연결과 STAGE 4~5를 중심에 두면 같은 시장의 **다른 문제를 푸는** 프로젝트가 됨.

### 차별화 포인트: Accountability Loop

| | Circleback | FollowIt |
|---|---|---|
| 해결하는 문제 | 회의록 작성이 귀찮다 | 회의에서 정한 일이 실행되지 않는다 |
| 회의를 보는 단위 | 회의 1건 | 이어지는 회의들의 맥락 (프로젝트) |
| 일이 끝나는 시점 | 태스크가 등록되는 순간 | 태스크가 완료되는 순간 |
| 성공 지표 | 회의록 품질, 절약한 시간 | **사람이 챙기는 부담의 감소** |
| AI의 역할 | 요약하고 추출 | 기억하고, 물어보고, 해석하고, 조정 |

## 2. 5단계 워크플로 상세

### STAGE 1. 연동
- **기본**: 기존에 사용하는 녹음 앱에서 회의 기록·전사문 가져오기 (MCP/API)
- **폴백**: Google Drive 업로드 감지 → STT API (한국어 + 화자 구분)
- **출력**: 타임스탬프 + 화자 라벨이 달린 전사문 + 회의 메타정보
- **리스크 대응**: 공개 API 없는 앱은 내보내기(export) 파일 업로드로 대체. MVP는 연동 가능한 앱 1개만 선정

### STAGE 2. 회의 연결 · 맥락 관리 (LLM ①)
- **목적**: 여러 프로젝트의 업무가 섞이지 않도록, 회의를 프로젝트·주제 단위로 묶어 관리
- **판단**: 이 회의가 이전 회의와 이어지는 회의인지 파악 (참석자, 주제, 언급된 액션 기준)
- **연결 효과**:
  - 기존 액션의 진행 상황을 이어서 추적 ("지난번에 하기로 한 설문은 끝났나?")
  - 이전 맥락을 추출 단계에 제공 → 담당자·기한 해석 정확도 상승
- **단계적 구현**: MVP는 사용자가 회의 묶음을 수동 선택 → 이후 자동 연결 추천 (확신도 낮으면 확인 요청)

### STAGE 3. 액션 · R&R (LLM ② + LLM ③)
- **추출 (LLM ②)**: 전사문 + 연결된 회의 맥락 → 구조화된 JSON
  - 결정사항, 액션아이템, 담당자, 기한
  - **근거 발화 + 타임스탬프** (환각 방지)
  - **확신도 (상/중/하)** (HITL 효율화)
  - 담당자/기한 없으면 반드시 "미정"
- **R&R 추천 (LLM ③)**: 담당자 "미정" 항목에 대해 추천
  - 팀원 역할 프로필 + 현재 업무량 참고, "왜 이 사람인지" 이유 제시
- **HITL**: 불명확한 항목만 Slack 승인 카드 발송
  - 수정/승인/거절 버튼, **n8n Wait 노드**로 사람 응답까지 대기
- **등록**: 승인된 것만 Notion DB에 생성 (회의·프로젝트 관계형 필드 포함)

### STAGE 4. 타임라인 (LLM ④)
- 선후관계 파악 ("설문 끝나야 분석 가능")
- 마일스톤(중간발표일 등)에서 역산하여 기한 제안
- 지연 발생 시 후속 업무 일정 변경사항 반영

### STAGE 5. 후속관리 F/U (LLM ⑤)
- **트리거**: 매일 09:00 (Cron)
- **로직**:
  ```
  Notion에서 미완료 태스크 조회
    ↓
  기한별 분류:
    D-2: 사전 리마인드 (Slack DM)
    D-day: 완료 확인 요청
    D+1~3: 지연 알림 + 사유 입력 요청
    D+3~: PM 에스컬레이션
    ↓
  담당자 답변 수신 (Slack Trigger)
    ↓
  LLM ⑤가 자유 답변 해석:
    completed / on_track / blocked / at_risk
    ↓
  분기:
    blocked → PM 에스컬레이션
    at_risk → 후속 업무 담당자 알림 + 새 일정 제안
    no_response (24h) → 재질문, 그래도 없으면 PM 알림
    ↓
  미완료·막힌 일 → 다음 확인 시점 또는 다음 회의 안건 (매주 금 17:00 초안 발송)
  ```
- → 다음 회의 녹음 → STAGE 1 (닫힌 루프)

## 3. AI가 꼭 필요한 이유

> 교수님이 반드시 물어볼 질문

1. **맥락 속 약속 파악**: "그럼 그건 제가 한번 볼게요" → 액션아이템 (키워드 규칙 불가)
2. **암묵적 기한 해석**: "중간발표 전까지는 돼야죠" → 10/24로 변환 (맥락 이해 필요)
3. **자유 답변 해석**: "아 그거 자료가 아직 안 와서요…" → blocked 분류 (규칙 불가)
4. **회의 연결 판단**: 제목이 달라도 같은 프로젝트의 후속 회의임을 참석자·주제·액션으로 파악

## 4. 리마인드 메시지 예시

```
[FollowIt] 리마인드
📋 마케팅 예산안 수정본 작성
👤 담당: 이대리
📅 기한: 내일 (10/31)
💬 근거: "이대리가 금요일까지 수정본 만들어주세요" (10/24 회의)

[완료] [진행 중] [막힘] [연기 요청]
```

## 5. 주간 리포트 예시

```
=== FollowIt 주간 리포트 (10/21~10/25) ===

📊 이행률: 7/10 (70%) ← 지난주 63%

✅ 완료 (7건)
  - A1. 마케팅 예산안 수정본 작성 (이대리, 기한 내)
  ...

⚠️ 미완료 (3건) → 다음 회의 안건 제안
  - A8. 고객 설문 설계 (최인턴, 3일 지연, blocker: 설문 도구 미정)
  ...

📋 다음 회의 안건 초안:
  1. [팔로업] 고객 설문 설계 blocker 해소 (최인턴)
  2. [팔로업] 서버 마이그레이션 일정 확정 (김팀장)
  3. [신규] ...
```

## 6. 전략적 제안: 경쟁하지 말고 올라타기

녹음·전사·추출은 기존 도구가 잘함. 시간을 여기에 쓰지 말고:
- 기존 녹음앱(노트테이커)의 결과물을 연동(MCP/API)으로 받아 STAGE 2~5에 집중
- 또는 검증된 n8n 템플릿을 가져와 커스텀

> "회의 AI 시장은 '기록'까지 왔습니다. 우리는 그 다음, '연결과 실행'의 빈칸을 채웁니다."

# Action Keeper (가칭) - 회의 이후를 책임지는 AI

> KAIST 경영대학 정보경영프로그램 (IMMS) | 2026 가을학기  
> 인공지능 비즈니스 전략 팀 프로젝트

**한 줄 정의**: 녹음된 회의를 LLM이 분석해 **할 일(TODO) → 담당자(R&R) → 일정(Timeline)**을 만들고, 일이 끝날 때까지 쫓아다니는 n8n 워크플로

## 문제 정의

### 누구의 문제인가
5~10명 규모의 프로젝트 팀 (스타트업, 사내 TF, 대학원 팀플).
그중 고통이 가장 큰 사람은 **회의를 주관하는 PM이나 팀장**.

### 왜 문제인가: 근본 원인 3가지

| 근본 원인 | 현상 | 관련 개념 |
|---|---|---|
| **주인 불명확** | "그거 누가 하기로 했죠?" 결정은 했는데 담당자를 안 정함 | 책임 분산 (Diffusion of Responsibility) |
| **기한 모호** | "다음 주쯤", "가능한 빨리" 같은 말로 끝남 | 목표 설정 이론의 구체성 부족 |
| **팔로업 부재** | 다음 회의 때 아무도 확인하지 않고 새 안건으로 넘어감 | 실행 격차 (Implementation Gap) |

### 기존 AI 회의 도구의 한계

**"기존 도구는 회의를 '기록'합니다. 우리는 회의를 '완결'합니다."**

| 단계 | 기존 회의 AI (Circleback 등) | Action Keeper |
|---|---|---|
| 녹음 → 텍스트 | O | O |
| 요약 + 액션 추출 | O | O |
| 담당자 미정 업무의 R&R 배정 | X | O (역할+업무량 기반 제안) |
| 일정 역산 + 선후관계 파악 | X | O (마일스톤 기준 기한 설정) |
| 진행 상황 추적 (팔로업 대화) | X | O (기한 전 질문, 답변 해석) |
| 지연 감지 → 일정 재조정 | X | O (후속 업무 담당자에게 알림) |
| 다음 회의 안건 자동 생성 | X | O (미완료/막힌 일 중심) |

## 솔루션: 5단계 워크플로

```
━━━ STAGE 1. 기록 ━━━
[트리거] 구글 드라이브에 녹음 파일 업로드 감지
   ↓
[STT] 음성 → 텍스트 + 화자 구분

━━━ STAGE 2. 추출 (LLM ①) ━━━
회의 분석 → 구조화된 JSON:
   • 결정사항 (Decision)
   • 액션아이템 (What)
   • 담당자 (Who): 명시됨 / 추정됨 / 미정
   • 기한 (When): 명시됨 / 추정됨 / 미정
   • 근거 발화 + 타임스탬프 ← 환각 방지
   • 확신도 (상/중/하)

━━━ STAGE 3. R&R + 타임라인 ━━━
[LLM ②] 담당자 미정 → R&R 제안
   • 팀원 역할 프로필 + 현재 업무량 참고
   • "왜 이 사람인지" 이유 제시
[LLM ③] 타임라인 생성
   • 선후관계 파악 ("설문이 끝나야 분석 가능")
   • 마일스톤에서 거꾸로 계산해 기한 제안
   ↓
[HITL] 회의 주관자에게 Slack 승인 카드 발송
   • 확신도 "하"인 항목만 강조
   ↓
[등록] Notion DB에 태스크 생성

━━━ STAGE 4. 추적 (LLM ④) ━━━
[스케줄] 기한 D-2에 담당자에게 Slack DM
   ↓
[LLM ④] 자유 답변 해석 → 상태 분류
   • 완료 / 순조 / 막힘(blocker) / 지연 예상
   ↓
[분기]
   지연 → 후속 업무 담당자 알림 + 새 일정 제안
   막힘 → PM 에스컬레이션
   무응답 → 24h 후 재질문, 그래도 없으면 PM 알림

━━━ STAGE 5. 순환 (LLM ⑤) ━━━
다음 회의 전날 안건 자동 생성
   • 완료/미완료/막힌 일/보류 결정
   ↓
→ 다음 회의 녹음 → STAGE 1 (끝나지 않는 고리)
```

### AI가 꼭 필요한 이유 (규칙으로는 안 되는 3가지)
1. **맥락 속 약속 파악**: "그럼 그건 제가 한번 볼게요" → 액션아이템 (키워드 규칙 불가)
2. **암묵적 기한 해석**: "중간발표 전까지는 돼야죠" → 실제 날짜 변환
3. **자유 답변 해석**: "자료가 아직 안 와서요…" → 막힘(blocker) 분류

## 성공 기준 (3층 구조)

| 층위 | 지표 | 측정 방법 | 목표 |
|---|---|---|---|
| **품질** | 액션아이템 재현율 | 수작업 정답과 비교 | >= 90% |
| | 액션아이템 정밀도 | 동일 | >= 85% |
| | 담당자/기한 정확도 | 동일 | >= 85% |
| | 승인 시 수정 비율 | 승인 카드 로그 | <= 20% |
| **성과** | **기한 내 완료율** | Notion 태스크 상태 | 기준값 대비 **+30%p** |
| | 주인 없는 액션 비율 | 등록 태스크 중 담당자 공란 | **0%** |
| | 지연 사전 감지율 | D-2에 미리 잡아낸 비율 | >= 70% |
| **효율** | 회의 후 정리 시간 | 수작업 시 직접 측정 | 30분 → 5분 |

### 실험 설계
- **전후 비교**: 도입 전 2주(수작업) vs 도입 후 6주
- **교란 변수**: 학기 후반 마감 압박으로 이행률 자연 상승 가능 → "AI만 잡아낸 액션 수" 등 시기 무관 지표 병행
- **표본 확대**: 다른 팀 1곳에 협조 → 데이터 확대

## 수행 계획

| 기간 | 할 일 | 산출물 |
|---|---|---|
| ~중간발표 (10/24) | 과거 회의 이행률 측정(기준값), 정답 라벨링 기준, STT 도구 테스트 | 기준값 데이터, 워크플로 설계도 |
| ~11월 초 | STAGE 1~2: 녹음 → 추출 → 승인 → Notion 등록 | 최소 기능 버전 |
| ~11월 중순 | STAGE 3: R&R 제안 + 타임라인 | 타임라인 뷰 |
| ~11월 말 | STAGE 4~5: 팔로업 DM, 답변 해석, 지연 알림, 안건 | 순환 고리 완성 |
| ~12월 중순 | 실제 운영 데이터, 지표 측정, 프롬프트 개선 | 성과 리포트 |
| 기말 (12/19) | 라이브 시연 + 결과 발표 | 최종 발표 |

## 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 화자 구분 실패 | 담당자 잘못 배정 | 화자 구분 지원 STT 사용, 회의 시작 시 자기소개 규칙 |
| 한국어 STT 오류 | 추출 품질 저하 | 도구 2~3개 비교 테스트 후 선택 |
| LLM이 담당자 지어냄 | 신뢰 상실 | 근거 발화 인용 필수, 근거 없으면 "미정" |
| 알림 피로 | 팀원이 DM 무시 | D-2 한 번만, 하루 알림 한 메시지로 묶기 |
| 녹음 동의/개인정보 | 윤리 문제 | 참석자 사전 동의, 원본 음성은 텍스트 변환 후 삭제 |

## 수업 이론 연결

| 수업 이론 | 프로젝트 적용 |
|---|---|
| 범용기술 보완혁신 (W2) | 기존 회의록 AI = "모터 끼워넣기". Action Keeper = 절차 재설계 (닫힌 루프) |
| 보완재로서의 판단 (W2) | 예측(추출)이 싸지면 보완재인 판단(HITL)의 가치 상승 |
| 전유성과 보완자산 (W3) | 모델 성능은 범용, 차별점은 워크플로+이행 데이터+조직 적합성 |
| 5 Forces (W6) | 회의록 AI 시장은 진입장벽 낮고 경쟁 치열 → 추적/팔로업이 해자 |
| VRIO (W6) | 축적된 이행률 데이터와 조직 맞춤 워크플로 = 모방 어려운 자원 |
| 정보재 과금 (W7) | 추출 한계비용 ~0, 추적 한계비용 >0 → 과금 구간 설계 |

## 비즈니스 확장

- **타깃**: Notion+Slack 쓰는 5~50인 스타트업, 컨설팅/에이전시 PM, 사내 TF
- **수익 모델**: 팀 단위 월 구독 (SaaS). 기존 도구를 대체하지 않고 그 사이를 잇는 실행 관리 계층
- **해자**: 쌓이는 데이터 — "누가 어떤 종류의 일을 얼마나 제때 끝내는지"가 R&R 추천 정확도를 계속 높임

## 기술 스택

- **백엔드**: n8n (노코드 워크플로)
- **STT**: 한국어+화자 구분 지원 API (비교 테스트 후 선정)
- **LLM**: Claude / GPT (5개 단계별 프롬프트)
- **태스크**: Notion API
- **알림**: Slack API
- **배포**: n8n Cloud 또는 클라우드 서버


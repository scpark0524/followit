# FollowIt (팔로잇) - 회의 이후를 책임지는 AI

> KAIST 경영대학 정보경영프로그램 (IMMS) | 2026 가을학기
> 인공지능 비즈니스 전략 팀 프로젝트 | TEAM_2: 김신애 · 박승찬 · 신지엽 · 윤경혜

**한 줄 정의**: 기존 녹음앱에서 회의 기록을 가져와 **이전 회의와 연결**하고, **할 일(TODO) → 담당자(R&R) → 일정(Timeline)**을 만들어 일이 끝날 때까지 쫓아다니는 n8n 워크플로

**서비스명**: FollowIt (팔로잇) — *follow + it*, 회의의 맥락을 기억하고 다음 액션을 끝까지 챙기는 AI 비서

## 문제 정의

### 누구의 문제인가
5~10명 규모의 프로젝트 팀 (스타트업, 사내 TF, 대학원 팀플).
그중 고통이 가장 큰 사람은 **회의를 주관하는 PM이나 팀장**.

### 왜 문제인가: 근본 원인 3가지

| 근본 원인 | 현상 | 관련 개념 |
|---|---|---|
| **주인 불명확** | "그거 누가 하기로 했죠?" 결정은 했는데 담당자를 안 정함 | 책임 분산 (Diffusion of Responsibility) |
| **기한 모호** | "다음 주쯤", "가능한 빨리" 같은 말로 끝남 | 목표 설정 이론의 구체성 부족 |
| **팔로업 부재** | 다음 회의 때 아무도 확인하지 않고 새 안건으로 넘어감 | 실행 격차 (Implementation Gap) |

### 기존 AI 회의 도구의 한계

**"기존 도구는 회의를 '기록'합니다. 우리는 회의를 '완결'합니다."**

| 단계 | 기존 회의 AI (Circleback 등) | FollowIt |
|---|---|---|
| 녹음 → 전사 → 요약 → 추출 → 등록 | O | O (기존 녹음앱에 연동, 올라타기) |
| 회의 연결 · 맥락 관리 | X | O (관련 회의 묶음, 기존 액션 이어 추적) |
| 담당자 미정 업무의 R&R 배정 | X | O (역할+업무량 기반 제안 + HITL 확인) |
| 일정 역산 + 선후관계 파악 | X | O (마일스톤 기준 기한 설정) |
| 진행 상황 추적 (팔로업 대화) | X | O (기한 전 질문, 답변 해석) |
| 지연 감지 → 일정 재조정 | X | O (후속 업무 담당자에게 알림) |
| 다음 회의 안건 자동 생성 | X | O (미완료/막힌 일 중심) |

## 솔루션: 5단계 워크플로

```
━━━ STAGE 1. 연동 ━━━
[트리거] 기존 녹음앱 연결 (MCP/API)
   • 회의 기록·전사문 가져오기
   • 폴백: 파일 업로드 + STT (화자 구분)

━━━ STAGE 2. 회의 연결 (LLM ①) ━━━
이전 회의와 이어지는 회의인지 파악
   • 관련 회의끼리 묶어 프로젝트별 맥락 관리
   • 기존 액션의 진행 상황을 이어서 추적
   • MVP: 수동 묶음 선택 → 이후: 자동 연결 추천

━━━ STAGE 3. 액션 · R&R (LLM ②③) ━━━
회의 분석 → 구조화된 JSON:
   • 결정사항 / 액션아이템 / 담당자 / 기한
   • 근거 발화 + 타임스탬프 ← 환각 방지
   • 확신도 (상/중/하)
담당자 미정 → R&R 제안 (역할·업무량 기반, 이유 제시)
   ↓
[HITL] 불명확한 항목만 Slack 승인 카드로 확인
   ↓
[등록] Notion DB에 태스크 생성

━━━ STAGE 4. 타임라인 (LLM ④) ━━━
   • 선후관계 파악 ("설문이 끝나야 분석 가능")
   • 마일스톤에서 거꾸로 계산해 기한 제안
   • 지연 발생 시 변경사항 반영

━━━ STAGE 5. 후속관리 F/U (LLM ⑤) ━━━
[스케줄] 기한 D-2에 담당자에게 Slack DM
   ↓
자유 답변 해석 → 완료 / 순조 / 막힘 / 지연 예상
   ↓
지연 → 후속 업무 담당자 알림 + 새 일정 제안
막힘 → PM 에스컬레이션
무응답 → 24h 후 재질문, 그래도 없으면 PM 알림
   ↓
미완료 업무 → 다음 확인 시점 또는 다음 회의 안건
→ 다음 회의 녹음 → STAGE 1 (끝나지 않는 고리)
```

### AI가 꼭 필요한 이유 (규칙으로는 안 되는 3가지)
1. **맥락 속 약속 파악**: "그럼 그건 제가 한번 볼게요" → 액션아이템 (키워드 규칙 불가)
2. **암묵적 기한 해석**: "중간발표 전까지는 돼야죠" → 실제 날짜 변환
3. **자유 답변 해석**: "자료가 아직 안 와서요…" → 막힘(blocker) 분류

## 성공 기준

**기준: "실제로 써봤을 때, 회의 이후 사람이 챙겨야 하는 부담이 줄었는가"**

두 단계로 측정:
- **① 구현 성공** — 회의 기록을 가져와 이전 회의와 연결하고, 액션 확인부터 후속관리까지 실제로 작동하는가
- **② 사용 성공** — 사용하면서 오류와 누락이 줄고, 사람이 직접 챙기는 시간과 부담이 줄었는가

| 축 | 질문 | 측정 방법 |
|---|---|---|
| **추적 정확성** | 연결된 회의의 액션을 빠짐없이 이어서 관리하는가 | 액션 누락·중복 건수, 담당자·기한 수정 건수 |
| **후속관리 신뢰성** | 필요한 시점에 확인하고, 답변·완료 여부를 제대로 반영하는가 | 예정된 F/U 중 정상 처리 비율, 누락·불필요 반복 알림 건수 |
| **실제 사용 가치** | 팀원들이 도움이 된다고 느끼고 계속 쓰고 싶은가 | 기한 내 완료율 변화, 유용성·알림 부담 평가, 지속 사용 의향 |

### 실험 설계
- **목표치는 초기 2주 실사용 결과를 보고 확정 (11/21)**
- 도입 전 수작업 관리 시간을 측정해 전후 비교. 데이터는 실사용 시작일부터 계속 기록
- 교란 변수: 학기 후반 마감 압박으로 이행률 자연 상승 가능 → "AI만 잡아낸 액션 수" 등 시기 무관 지표 병행
- 표본 확대: 다른 팀 1곳에 협조 → 데이터 확대

## 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 녹음앱 공개 API/MCP 부재·제한 | 연동 단계 차질 | 내보내기(export) 파일 수동 업로드 폴백, 연동 가능 앱 사전 조사 후 1개 선정 |
| 화자 구분 실패 | 담당자 잘못 배정 | 화자 구분 지원 STT 사용, 회의 시작 시 자기소개 규칙 |
| 한국어 STT 오류 | 추출 품질 저하 | 도구 2~3개 비교 테스트 후 선택 |
| 회의 연결 오판 | 다른 프로젝트 업무 섞임 | MVP는 수동 묶음 선택, 자동 추천은 확신도 낮으면 확인 요청 |
| LLM이 담당자 지어냄 | 신뢰 상실 | 근거 발화 인용 필수, 근거 없으면 "미정" |
| 알림 피로 | 팀원이 DM 무시 | D-2 한 번만, 하루 알림 한 메시지로 묶기 |
| 녹음 동의/개인정보 | 윤리 문제 | 참석자 사전 동의, 원본 음성은 텍스트 변환 후 삭제 |

## 수업 이론 연결

| 수업 이론 | 프로젝트 적용 |
|---|---|
| 범용기술 보완혁신 (W2) | 기존 회의록 AI = "모터 끼워넣기". FollowIt = 절차 재설계 (닫힌 루프) |
| 보완재로서의 판단 (W2) | 예측(추출)이 싸지면 보완재인 판단(HITL)의 가치 상승 |
| 전유성과 보완자산 (W3) | 모델 성능은 범용, 차별점은 워크플로+회의 맥락·이행 데이터+조직 적합성 |
| 5 Forces (W6) | 회의록 AI 시장은 진입장벽 낮고 경쟁 치열 → 회의 연결·추적·팔로업이 해자 |
| VRIO (W6) | 축적된 회의 맥락 그래프와 이행률 데이터 = 모방 어려운 자원 |
| 정보재 과금 (W7) | 추출 한계비용 ~0, 추적 한계비용 >0 → 과금 구간 설계 |

## 비즈니스 확장

- **타깃**: Notion+Slack 쓰는 5~50인 스타트업, 컨설팅/에이전시 PM, 사내 TF
- **수익 모델**: 팀 단위 월 구독 (SaaS). 기존 녹음앱을 대체하지 않고 그 위에 올라타는 실행 관리 계층
- **해자**: 쌓이는 데이터 — 회의 간 맥락 그래프 + "누가 어떤 종류의 일을 얼마나 제때 끝내는지"가 연결·R&R 추천 정확도를 계속 높임

## 기술 스택

- **백엔드**: n8n (노코드 워크플로)
- **연동**: 기존 녹음앱 MCP/API (폴백: Google Drive 업로드 + 한국어·화자 구분 STT)
- **LLM**: Claude / GPT (단계별 프롬프트)
- **태스크**: Notion API
- **알림**: Slack API
- **배포**: n8n Cloud 또는 클라우드 서버

## 저장소 구조

```
followit/
├── CLAUDE.md          # 프로젝트 맥락 (Claude Code용)
├── workflows/         # n8n에서 내보낸 JSON (단계별 분리)
├── prompts/           # 회의연결·추출·R&R·상태해석 프롬프트 + JSON 스키마
├── eval/              # 정답 라벨, 정확도 측정 스크립트, 결과
├── data/samples/      # 회의록 텍스트 샘플 (음성 원본 제외)
├── scripts/           # 발표자료 생성 등 스크립트
└── docs/              # 기획, 고스트 덱, 발표자료
```

# LLM ① 회의 연결 판단 프롬프트

## 용도
STAGE 2: 새로 들어온 회의가 기존 회의 묶음(프로젝트)과 이어지는지 판단하고, 이어서 추적할 기존 액션을 찾음

> MVP 단계에서는 사용자가 회의 묶음을 수동 선택하므로 이 프롬프트는 2단계(11/8~)부터 사용.
> 확신도가 "하"이면 자동 연결하지 않고 사용자에게 확인을 요청할 것.

## 프롬프트

```
당신은 회의 맥락 관리 전문가입니다. 새 회의 전사문과 기존 회의 묶음 목록을 보고,
이 회의가 어느 묶음에 속하는지(또는 새 묶음인지) 판단해주세요.

## 규칙
1. 판단 근거는 참석자 구성, 논의 주제, 언급된 기존 액션아이템 3가지입니다.
2. 전사문에서 기존 액션을 언급한 발화가 있으면 반드시 인용하세요.
   (예: "지난번에 하기로 한 설문은 어떻게 됐어요?" → 기존 액션 A8과 연결)
3. 확신이 없으면 추측하지 말고 확신도를 "하"로 표시하세요. 잘못된 연결은
   다른 프로젝트의 업무가 섞이는 것이므로 미연결보다 해롭습니다.
4. 여러 프로젝트가 한 회의에서 논의됐다면 주된 묶음 하나를 고르고,
   나머지는 related_groups에 넣으세요.

## 기존 회의 묶음 목록
{meeting_groups}
<!-- 각 묶음: id, 이름, 최근 회의 날짜, 참석자, 미완료 액션 목록 -->

## 새 회의 정보
- 날짜: {meeting_date}
- 참석자: {attendees}

## 전사문
{transcript}

## 출력 형식 (JSON)
{
  "linked_group_id": "묶음 id 또는 null (새 묶음)",
  "new_group_name": "새 묶음일 경우 제안 이름, 아니면 null",
  "confidence": "상 | 중 | 하",
  "reasons": ["판단 근거 1", "판단 근거 2"],
  "mentioned_actions": [
    {
      "action_id": "기존 액션 id",
      "quote": "근거 발화 원문",
      "timestamp": "00:00",
      "status_hint": "완료 언급 | 진행 언급 | 막힘 언급 | 언급만"
    }
  ],
  "related_groups": ["부차적으로 논의된 묶음 id"]
}
```

## 평가 기준 (eval/ 연동)
- 연결 정확도: 수작업 정답 묶음과 일치 비율
- 기존 액션 매칭 재현율: 전사문에서 언급된 기존 액션을 놓치지 않는 비율
- 과연결(false link) 건수: 다른 프로젝트를 잘못 묶은 횟수 — 가장 치명적, 0건 목표
